Privacy policy

We don't collect your data.

privacytracker runs on your machine. There is no server-side account system, analytics pipeline, or data broker in the loop. Because "we don't collect anything" is cheap to say, this page also lists every third-party endpoint the app may contact while you use it, so the full shape of what goes over the wire is visible.

Data Not Collected

The developer does not collect any data from this app.

Third parties the app talks to#

When you use privacytracker, it calls a small number of public endpoints on your behalf. Nothing here sends your personal identifiers, but these hosts see standard HTTP request metadata (your IP, your User-Agent, the URL you're fetching), so we list them all.

Nothing in the browser talks to a third party. Inter, the icons, every script and stylesheet are served from the same origin as the app. The list below is everything the server fetches on your behalf.

App Store & metadata

Required for the core loop. Without these the app can't find, identify, or sync iOS apps.

Apple: iTunes Search API

Required
itunes.apple.com/search · itunes.apple.com/lookup
When it runs
Whenever you search for an app by name during onboarding, or when the app syncs metadata (version, developer, icon).
What we send
The app name you typed, or a known Apple track ID, plus the country code you picked (default AU).
What we receive
A public-catalogue JSON payload: track ID, name, developer, icon URL, App Store URL, current version.

Apple's privacy policy ↗

Apple: App Store web listing

Required
apps.apple.com/<country>/app/<slug>/id<id>
When it runs
During every privacy-label scrape: initial import, manual resync, and the 30-minute background sync.
What we send
A standard browser-style HTTP GET with a Referer of apps.apple.com. No cookies or identifiers.
What we receive
The App Store page HTML, which the app parses for the privacy label JSON blob and developer's privacy policy link.

Apple: mzstatic image CDN

Required
is1-ssl.mzstatic.com (and siblings)
When it runs
Only when your browser renders an app icon returned by the Apple lookup. Apple host the icons here directly.
What we send
Nothing beyond a standard image request.
What we receive
PNG / JPG icon bytes.

Developer privacy policies

Directly from whichever host the developer publishes on. We don't route this through any intermediary.

Developer-published privacy policy URLs

Required
Whatever host the developer links to on the App Store page
When it runs
Each time you resync an app or the 30-minute background sync runs, we follow the privacy-policy link Apple publishes on the App Store page for that app.
What we send
A standard HTTP GET. No cookies or identifiers.
What we receive
The HTML of the developer's published privacy policy.

Historical archives (opt-in)

Only contacted if you explicitly run a Wayback import from Settings → Wayback import.

Internet Archive: Wayback availability API

On-demand
archive.org/wayback/available
When it runs
Only when you explicitly run a historical Wayback import (once per app, per calendar quarter).
What we send
The App Store URL you're trying to back-fill, plus a target timestamp. No cookies or identifiers.
What we receive
The closest available Wayback capture URL for that timestamp.

Internet Archive's terms ↗

Internet Archive: Wayback Machine replay

On-demand
web.archive.org/web/<timestamp>id_/<original>
When it runs
Follow-up to the availability API. Downloads the archived App Store HTML so we can re-parse it against the same schema as a live scrape.
What we send
A standard HTTP GET.
What we receive
The archived HTML with Wayback's toolbar injector disabled (id_ suffix).

Internet Archive: Save Page Now

On-demand
web.archive.org/save/<url>
When it runs
Only fired when a historical import finds an empty quarter with no existing capture. In that case we ask the Archive to create one for future runs.
What we send
The public App Store URL of the app. Nothing else.
What we receive
An HTTP response indicating whether the snapshot request was accepted; no data stored client-side.

AI providers (opt-in)

Not contacted unless you turn on AI summaries in Settings → AI Policy Summaries and pick a provider. The default is "disabled".

OpenAI API

Optional
api.openai.com
When it runs
Only if you set the AI provider to "OpenAI" in Settings → AI and supply your own API key.
What we send
The scraped developer privacy policy text plus a structured-summary prompt. No app data beyond what's in the policy.
What we receive
A JSON summary keyed by the lenses defined in lib/privacy-policy.ts.

Anthropic API

Optional
api.anthropic.com
When it runs
Only if you explicitly set the AI provider to "Anthropic" in Settings → AI and supply your own API key.
What we send
The same scraped policy text + summary prompt.
What we receive
A JSON summary.

Custom / local AI endpoint

Optional
Whatever base URL you configure (default 127.0.0.1:11434)
When it runs
Only if you set the AI provider to "Custom" in Settings → AI. Intended for local models. No data leaves your network if the endpoint is local (Ollama, LM Studio, llama.cpp).
What we send
Scraped policy text + summary prompt.
What we receive

Going fully offline#

The website you're reading right now makes zero third-party connections. Inter is self-hosted and every asset is served from the same origin. Server-side, you can cut the last two optional outbound calls from inside the app:

  • AI summaries: open Settings → AI Policy Summaries and set the provider to "Disabled", or point it at a local Ollama endpoint to keep summarisation on-device.
  • Wayback imports: leave them alone. They're opt-in, so never running them keeps the Internet Archive out of the picture entirely.

That leaves only Apple's own endpoints (iTunes Search + App Store pages) and the developer privacy-policy links you explicitly scrape, both of which are the point of the app.

Other privacy-policy summarisers#

privacytracker's AI summaries are one way to make sense of long policy documents, but they're opt-in and narrow by design. We only summarise policies for apps you've actively added. Two long-running third-party projects tackle the same problem across a much wider catalogue:

  • Terms of Service; Didn't Read (ToSDR) ↗: community-reviewed grades for thousands of services, each broken down into plain-language "points" (good / neutral / blocker) with links back to the clause they came from.
  • PrivacySpy ↗: open-source, machine-readable scoring of privacy policies across a curated list of services, with rubric-backed reasons for every rating.

privacytracker has no affiliation with either project. They're listed because they're a useful complement to what this app does. If you decide to use either service, read their terms and privacy policy first.
