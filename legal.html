next v16.2.12

How we use it: The entire app is a Next.js App Router project. Every page, every /api/ route, the background scheduler bootstrap, and the build/serve toolchain come from Next.

React framework from Vercel — file-system routing, server components, API routes, dev server, production build pipeline.

next-intl v4.13.4

How we use it: Internationalisation for the app's UI strings — message catalogues, locale-aware formatting, route segmentation by locale.

i18n library purpose-built for Next.js App Router. Server- and client-component aware.

Website ↗ Source ↗ npm ↗

react v19.2.7

How we use it: Powers every interactive surface — the onboarding wizard, settings, the app detail view, the bell, the task centre.

Core React library — component model, hooks, reconciler primitives.

Website ↗ Source ↗ npm ↗

react-dom v19.2.7

How we use it: Mounts components into the browser DOM and server-renders pages for the initial HTML response.

React's DOM renderer + hydration entry points.

Source ↗ npm ↗

react-joyride v3.0.2

How we use it: Powers the optional first-run guided tour ("coachmarks") that walks new users through the dashboard, privacy map, and settings on first launch.

React component library for in-app product tours and step-by-step walkthroughs.

Website ↗ Source ↗ npm ↗

better-sqlite3 v12.11.1

How we use it: The entire persistence layer. Apps, privacy types, change snapshots, notifications, settings — all of it. WAL journal mode, foreign keys on, 5-second busy timeout.

Synchronous, zero-config SQLite binding for Node — binary wheel built against N-API.

Source ↗ npm ↗

echarts-for-react v3.0.2

How we use it: Used by every chart component to declaratively bind ECharts options to React state.

Thin React wrapper around ECharts — handles mount/unmount and option diffing.

Source ↗ npm ↗

marked v18.0.5

How we use it: Renders the markdown returned by the AI policy summariser into HTML for the app detail page.

Fast markdown parser and compiler. Supports CommonMark and most GFM extensions.

Website ↗ Source ↗ npm ↗

@types/* v19.2.17 dev only

How we use it: TypeScript type definitions for React, Node, better-sqlite3, etc. Dev-time only — provides autocomplete and type checking. Not shipped to users.

DefinitelyTyped community-maintained types. The version shown matches @types/react; the rest track their own packages.

Source ↗

cross-env v10.1.0 dev only

How we use it: Sets BUILD_STANDALONE=1 before next build so the same npm script works on macOS, Linux, and Windows.

Tiny shim that sets environment variables the same way across Unix and Windows shells.

Source ↗ npm ↗

echarts v6.1.0

How we use it: Powers the data-viz panels — privacy heatmap, category frequency bars, stacked area timeline, per-app severity strips, the small multiples on the stats page.

Apache ECharts — interactive charting library originally from Baidu, now an Apache top-level project.

Website ↗ Source ↗ npm ↗

tesseract.js v7.0.0

How we use it: Optional, local-only OCR. Used in onboarding when the user imports iOS app screenshots — Tesseract extracts the visible app names so we can look them up. No image leaves your device.

WebAssembly port of the Tesseract OCR engine. Runs entirely in the browser or in Node.

Website ↗ Source ↗ npm ↗

typescript v6.0.3 dev only

How we use it: Every source file under app/ and lib/ is TypeScript. The compiler runs at build time only — it isn't shipped to users.

Typed superset of JavaScript from Microsoft; compiles to JS.

Website ↗ Source ↗

@tauri-apps/cli v2.11.4 dev only

How we use it: Optional desktop-build path. Used by npm run tauri:build to package the app as a native desktop binary. Not shipped to end-users of the web build.

Command-line tool for building Tauri desktop apps (Rust-backed webview wrappers).

Website ↗ Source ↗

Inter typeface v4.1

How we use it: Primary UI typeface for both the app and this website. Shipped as two woff2 files in /assets/fonts/ with the licence file alongside, declared via @font-face. Served from the same origin — no Google Fonts round-trip.

Sans-serif typeface designed for UI by Rasmus Andersson. Variable-font release shipping upright + italic axes across weights 100–900.

OpenDyslexic typeface v1.0.3

How we use it: Optional accessibility font in the app. Activated via the footer accessibility toggles (Dyslexia-friendly font). Shipped self-hosted alongside the rest of the fonts — no third-party CDN round-trip, so the feature works offline.

Typeface with weighted letterforms designed to improve readability for some readers with dyslexia. Originally designed by Abelardo Gonzalez, derived from Bitstream Vera Sans.
